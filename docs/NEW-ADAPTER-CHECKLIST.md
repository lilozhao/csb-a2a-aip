# 新注入适配器上线 checklist

> 2026-09-16 建立 · 缘起：为 Hermes 系写适配器时，**同名函数 ≠ 同契约** 一晚上踩了三次
> 每次修好一层，下一层才浮出来 —— 这不该靠人肉逐层剥。
> 参照物：`adapters/openclaw-gateway.js`（**唯一被实践证明可用的参照契约**）

---

## 〇、先跑门禁（机械化，不靠人眼）

```bash
node tests/adapter-contract.test.js      # 适配器契约门禁（含假适配器反向自检）
```

它查：方法齐备 · 纯函数行为（`buildInjectMessage`/`detectRefusal`/`resolveConfig`）· **`fetchResult` 成功返回必须含 `result`** · `CONTRACT` 声明 · canonical 参数名 `sinceMs` 被接受。
契约定稿：`adapters/CONTRACT.md`（**single source of truth**）。

## 一、必须逐项对照的四处（缺一处 = 静默失败）

| # | 对照项 | 怎么查 | 踩过的实例 |
|---|---|---|---|
| **1** | **参数名** | bridge 调用处的实参名，逐个与 adapter 的形参对照 | `sinceMs`（bridge）vs `since`（adapter）→ 时间下界丢失，静默 |
| **2** | **返回结构** | bridge 消费处**每个字段的取值路径**，与 adapter 返回对象**逐字段**对照 | bridge 读 `resp.result` → adapter 返 `{ok,matched,reply,raw}` **无 result** → `collectTexts(undefined)` → `[]` → **从不解析** |
| **3** | **缺省语义** | 同名参数的**默认值/缺省行为**是否一致 | `fetchResult(tid,{to,sessionKey,sinceMs,limit})` 无 `path`；OpenClaw 自带实现不看、Hermes 回落保守 `C` → 只在一个系暴露 |
| **4** | **能力声明** | adapter 有特殊能力（如需特殊路径/参数）时，**主动向 bridge 声明** | 新增 `adapter.confirmReadPath()` → bridge 未显式配置时问适配器，宿主只配一个 env |

## 二、验收规范：命令内容最小化

> 2026-09-16 实测：**同一链路**，最小委托 **58.9s** vs 首验 **106.7s**。
> 把「验收指令」和「要求回证的证据」写在同一个委托里，会让注入回合**自阻塞**（它在等一个只有确认后才出现的证据）。

- ✅ **执行委托**：只写「要做的动作」（幂等、单条、有界）+ 副作用判据（nonce）
- ✅ **证据汇报**：**另开一轮 / 异步**给（不写进执行委托）
- ❌ 不要在委托里要求「回报确认过程的日志行」——那只是确认之后才存在的东西

## 三、验证方法（别只看单个系的绿灯）

1. **跑参照适配器的测试**，确认自己的 adapter 也过同一套断言
2. **在 bridge 消费端加一条断言**：`collectTexts` 输入=自己的返回形状 → 期望非空
   （本次真因就是「日志里 path 正确、轮询正常，却零 `parsed=` 行」——**没读 vs 读了没认出来**要能区分）
3. **换一台配好 env 的机器再跑一遍**（本机绿 ≠ 通过）
4. **端到端跑一次「最重」的路径**（L3 write/shell 全流程），而不是只跑 read

## 三、症状速查（背下来）

| 症状 | 含义 |
|---|---|
| 无 `parsed=` 行、且`path=` 显示默认值 | **根本没读**（path/参数没透传） |
| 有轮询、`path=` 正确、却无 `parsed=` | 在读了，但**返回结构/文本没进来** 或 **库里还没那条**（区分两者：先看 `collectTexts` 那一层） |
| 确认「已送达、已回复」，任务仍超时 | 十有八九是**结构/参数对不上**，不是链路不通 |

## 四、元教训

> **同名函数 ≠ 同契约。**
> 「接口同形」只是**签名**一致；**实参名、返回形状、缺省语义**三者任一错位，都会造成**静默失效**——而静默失效比报错更贵。
> ⇒ 新增实现时，**以「参照实现」为准逐字段抄**，而不是按理解写。
