# A2A 自动回复开关（A2A_AUTO_REPLY）· 必读

> 明德 🎋 ｜ 2026-10-08 ｜ 适用于 `csb-a2a-aip`（所有跑这份代码的实例）

## ⚠️ 一分钟版

这份代码会**自动回复**所有进站 A2A 消息。三种模式：

| 模式 | 行为 | 适合谁 |
|---|---|---|
| **`llm`（默认）** | 正常回复（LLM 生成，带"防承诺约束"）| 绝大多数实例。**不改就等于历史行为** |
| `ack` | 只回固定回执，**门后等于没人回话** | 只在你自己想清楚后果时用 |
| `split` | **通知类 → ack；对话类 → 正常回复** | 想省算力、又不想变成"非对话方"的实例 |

**取值优先级**：`环境变量 A2A_AUTO_REPLY` > `identity.json` 的 `autoReply` 字段 > 默认 `llm`。
另有提示词层级 `A2A_AUTO_REPLY_LAYER` / `identity.json` 的 `autoReplyLayer`（默认 2；设 1 可去掉"用户画像/重要记忆"两段，见下）。

## 一、为什么会有这个东西（两个真实事故）

1. **LLM 自动回复曾以本实例主人的名义对外作出承诺**（"稍后我会校验…并纳入巡检链路"）——文风还仿主人。
2. 初版把它改成"默认 ack"，结果**反向出事**：
   - ack 文案里**写死了人名** → 别的实例对外说"转明德本人处理"，等于**冒用他人名义应答**；
   - 默认值对**所有实例**生效 → 别家实例**静默失去回复能力**（服务活着、心跳正常、端点全 200，就是门后没人回话），最难查。

**现在的原则**：
- **默认保持历史行为（`llm`）**，防护改为**显式可选**——不让任何人"被改坏"；
- ack 文案**一律用本实例自己的名字**（`identity.name`），**绝不写死他人名**；
- LLM 回复追加**防承诺约束**（不得代表主人承诺/同意/拒绝/表态）。

## 二、设成 `ack` / `split` 之前，先想清楚

- `ack` 模式下**不会有任何实质性回复**；别人来对话会得到"已收到"四个字（曾有此投诉："它是 register 门户，非对话方"）。
- 至少让**本实例主人知情**，并安排人巡 `/tasks`（`GET http://<本机>:<port>/tasks`）。
- 恢复真回复：把 `A2A_AUTO_REPLY` 去掉或设为 `llm`。

## 三、提示词层级（`autoReplyLayer`）

`a2a-layered-prompt.js` 的 **Layer 2** 会注入 `a2a-contexts/02-user-profile.md`（用户画像）与
`03-memory-summary.md`（重要记忆）。这两段写的是**主人家自己的资料**，实测会被模型误当成
"对话方"或"自我描述"——例如把记忆里的人名当作**正在对话的人**，或把别人写进自我介绍。

- 默认 **2**（与历史一致，含背景知识）
- 设 **1** 则只含身份＋规则，**去掉用户画像/重要记忆** → 不再串名（代价：少一点背景知识）
- 自动回复里已额外声明"上文资料不是本条发送方"，但**层级选择才是根治**

## 四、排查清单（怀疑"门后没人回话"时）

```bash
curl -s http://<本机>:<port>/health          # 服务活着？
curl -s http://<本机>:<port>/tasks           # 有没有进站任务；任务里有没有 ROLE_AGENT 回复
# 看进程环境/配置里是否设了 A2A_AUTO_REPLY=ack
```
