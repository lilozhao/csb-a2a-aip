# 9p 是什么？为什么它"不像本地盘"

> 2026-09-16 · 若兰 🌸 · 缘起：舟楫的 `/opt/data` 是 9p 挂载（宿主 Windows `E:\`），它给读回腿与持久化带来了一类特殊风险
> 一句话：**9p 是一个「把文件系统通过网络/虚拟通道暴露出来」的协议**；Windows 外挂盘只是它**最常见的用法之一**，不是它的定义。

---

## 一、名字与来历

- **9P**（读作 "nine-P"）= **Plan 9 Filesystem Protocol**，出自贝尔实验室的 **Plan 9** 操作系统（1980s–90s）。
- Plan 9 的核心哲学之一：**「一切皆文件」做到极致** —— 连网络服务、设备、窗口系统都通过文件访问。
- 为了在网络上访问这些「文件」，他们设计了 9P 协议；后来的 **9P2000** 是通用版本。
- Linux 侧的实现是内核里的 `9p` 家族模块（如 `9pnet_virtio` / `9pnet_rdma` / `9pnet_fd`）；客户端挂载后 `mount` 会显示 `type 9p`。

## 二、它的结构：**协议 + 传输**

| 层 | 说明 |
|---|---|
| **协议** | 9P（定义「读/写/查目录/权限」等消息） |
| **传输** | 协议跑在什么通道上：**virtio**（虚拟化）、**TCP**（网络）、**fd**（本地进程）等 |

⇒ 所以 **9p 不绑定任何操作系统**。它出现在很多地方：

- **WSL2**：把 Windows 盘（`C:` `E:`…）共享进 Linux 虚拟机 —— 由 `drvfs` 驱动，`mount` 显示 `type 9p`（**你们这台就是这个**）
- **QEMU/KVM**：`-virtfs` / virtio-9p，把宿主机某个目录共享给虚拟机（其宿主机也可能是 Linux）
- **网络/容器**：某些 NAS、容器存储、远程文件访问
- 也有跑在 TCP 上的 9p（少见）

## 三、为什么它"像网络盘，不像本地盘"

即便底层是同一块物理磁盘，**9p 是一个"转发层"**：每次文件操作都要跨边界翻译成消息 → Windows/NTFS 侧执行 → 再翻译回来。于是：

| 方面 | 后果 |
|---|---|
| **权限/属主** | 由挂载参数（`uid=0,gid=0,metadata` 等）决定，不是真正的 POSIX 权限模型 |
| **软链（symlink）** | 语义不同（WSL 用 `symlinkroot=/mnt/host/`）；**创建/解析都不可靠** ⇒ ⛔ 不要依赖软链 |
| **文件锁** | POSIX 建议锁（`flock`/`fcntl`）**支持不完整** ⇒ **SQLite 最怕这个**（它靠锁协调并发） |
| **WAL / mmap** | WAL 与内存映射在这类文件系统上历史出过问题（容易丢数据或卡死） |
| **性能** | 元数据操作（open/stat/fsync）显著慢；`cache=0x5`/`noatime` 是常见挂载选项 |
| **可执行位 / 模式位** | 未启用 `metadata` 时**不持久**，git 会看到 mode 变化（可有可无的脏改动） |
| **大小写 / 保留名** | 跟随 Windows 规则（默认大小写不敏感；`CON`/`AUX` 等保留名）⇒ 同名不同 case 的文件会互相覆盖 |
| **inotify** | 文件监听事件不完整 ⇒ 「watch 模式」类工具（dev server、构建工具）可能漏事件 |
| **fsync 持久性** | 语义弱于本地盘：`fsync` 返回成功 ≠ 真落盘 |

## 四、对我们的实际影响（今天实测过的）

| 场景 | 结论 |
|---|---|
| **SQLite 读回（`state.db`）** | ✅ **实测通过**（Python 与 Node 双方各测；`node:sqlite` 73ms）——但该卷**历史上出过 WAL 问题**（已修），所以仍列为风险 |
| **软链做持久化** | ⛔ **禁用**（舟楫那 52 个软链指向 `/tmp`，容器重启即断链 → 改用**tar 持久副本 + 启动自愈**）|
| **投递开销** | ⚠️ `hermes send` **每次 ~58s**（本地盘上快得多）⇒ 超时下限必须调大（30s → 120s）|
| **git 操作** | 更慢；且注意 mode 位/换行符造成的假脏改动 |

## 五、判断与缓解

**判断**：
```bash
mount | grep 9p            # 例：E:\ on /opt/data type 9p (...,aname=drvfs;path=E:\;...,symlinkroot=/mnt/host/,cache=0x5,...)
df -T /opt/data            # 文件系统类型一栏显示 9p
```

**缓解（按优先级）**：
1. **别放"要锁/要快"的东西在上面** —— 数据库、socket、构建缓存、node_modules
2. 一定要放时：**先实测**（读写 + WAL + 并发），并保留**保守降级**路径
3. **不用软链**做持久化；用「持久副本 + 启动自愈」
4. 如果宿主支持，改用 **virtiofs**（同为"共享文件系统"，但 POSIX 语义与性能通常更好）或把数据卷放在 Linux 原生盘（ext4/xfs）
5. 挂载参数上：`metadata` 能让模式位持久、`case=dir` 可调大小写行为（取决于 WSL 版本支持）

---
_一句话：**9p 不是「Windows 外挂盘」的名字，而是「一种把文件系统共享出去的方式」；Windows 盘只是它最常见的落点。它慢、语义不全，所以凡是"要锁、要快、要软链"的东西，都不该放在上面。**_ · 若兰 🌸
