# Hermes 系两实例落地差异对照（墨丘 vs 舟楫）

> 2026-09-16 · 若兰 🌸 · 数据来源：两实例自述 + 我方实测（`bridge-receipt` / 命令原文）
> 目的：把「**框架共性**」（同框架必有）与「**落地差异**」（每台机不同）分开 ——
> **共性决定适配器怎么写，差异决定适配器要暴露哪些开关。**

---

## 一、总览

| 维度 | 墨丘 | 舟楫 | 差异性质 |
|---|---|---|---|
| 框架 | Hermes Agent v0.20.0 | Hermes Agent v0.20.0 | **共性** |
| 运行形态 | Docker 容器 | Docker 容器（镜像 `hermes-agent:v0.20.0`） | 共性 |
| 进程管理 | **s6-supervise**；主进程 = `hermes gateway run --replace` | **s6-overlay**（PID1 = `s6-svscan`）；服务 `main-hermes` / `gateway-default` / `dashboard` | 同族不同封装 |
| Python | 3.13.5（venv） | 3.13.5（venv） | 共性 |
| Node（A2A server 侧） | —（未报） | **v26.5.1** | **落地差异** |
| 模型 | deepseek-v4-flash（`fallback_providers` **为空**） | 主 deepseek-v4-flash；A2A 侧百炼 qwen3.6-flash + deepseek fallback | **落地差异** |
| **落盘** | **本地盘**（`HERMES_HOME=/opt/data`） | ⚠️ **9p 挂载**（宿主 Windows `E:\`，502G，87% 用） | ★ **最大差异** |
| 平台适配器 | 飞书（WS 出站长连接） | 飞书 + 微信 gateway | 落地差异 |
| A2A server | `node server_v5.js`（v5.0.0） | `node server_v5.js`（v5.0.0） | **共性**（都是我们的代码） |

## 二、★ 三处**对注入腿有实质影响**的差异

### 1. 落盘后端：本地盘 vs 9p（影响**读回腿 + 持久化**）

| 项 | 墨丘（本地盘） | 舟楫（9p） |
|---|---|---|
| `state.db` 规模 | 468 MB（gateway 在写） | 未报，同型 |
| 读回实测 | 6 ms（FTS5 0.02s） | **73 ms**（`node:sqlite`，复测 139ms） |
| 软链 | 可用 | ⛔ **不可依赖**（9p symlink 语义不同） |
| WAL | 历史无异常 | 历史出过问题（v0.20.0 / SQLite 3.53.4 已修） |
| 结论 | 读回腿默认可用 | **读回腿可用，但首次必须实测**；持久化**禁用软链** |

> 舟楫实测：Python `sqlite3` 与 Node `node:sqlite` **都通过了**基本读写 + WAL + 重开。
> 但 Python 版通过 ≠ Node 版通过 —— **必须各自实测**。

### 2. 环境注入源：`.env` vs **watchdog 脚本**（影响**配置放哪儿**）

| | 墨丘 | 舟楫 |
|---|---|---|
| 配置落点 | `/opt/data/.env`（11 个变量） | ⚠️ **仓库内无 `.env`** —— 由 `/opt/data/scripts/a2a-watchdog.sh` **导出** |
| 生效方式 | 重启 A2A | 重启 A2A（同） |
| 启示 | 走 `.env` | **必须改启动脚本**；且该脚本同时负责拉起进程 |

⇒ **适配器不该假设配置在 `.env`**；文档里应写「配置落点以宿主启动方式为准」。

### 3. 本机 CLI 开销：投递腿的**固有耗时差 10 倍**（影响**超时下限**）

| 项 | 墨丘（本地盘） | 舟楫（9p） |
|---|---|---|
| `hermes send` 单次 | 未单独测（本地盘，快） | ⚠️ **~58 s / 次**（冷 57.8s、热 57.9s —— **固有开销，非冷缓存**） |
| `hermes -z` 注入回合 | 106.7s（首）→ 58.9s（最小委托） | **7–8 s** |
| 端到端 L3 | **58.9 s** | **233.2 s** |

⇒ 由此暴露真缺陷：**confirm 侧默认 30s 投递上限在 9p 上必超** → 已改为 `max(调用方, 120s)`。

## 三、其余差异（对注入腿无实质影响，但值得记）

| 项 | 墨丘 | 舟楫 |
|---|---|---|
| `hermes` 可执行 | `/opt/hermes/.venv/bin/hermes` | 同路径（310 字节 shim）· **不在 PATH** | 
| `identity.json` | 无 `adapter` 字段（部署时后加的 `platform`） | ⚠️ **有 `adapter` 字段**（= LLM 路由，`direct`） |
| A2A 服务启动 | `start-a2a.sh` | ⚠️ **无该脚本**（有 `start-v5.sh`）；实际由 **watchdog** 拉起 |
| 审计目录 | 曾硬编码致 `EACCES` | 已配 `A2A_CMD_AUDIT_LOG` |
| 懒安装目录 | `/tmp/lark-fast`（易失）→ 宿主用 env 兜住 | ⚠️ 同问题，**52 个软链** → 改 **tar 持久副本 + watchdog 启动自愈** |
| 遗留 WORKING 任务 | 未报 | **6 个**（进程中断 + 无超时回收）|
| 时区 | 容器 **TZ=UTC**（按本地时间过滤差 8h） | 未报（同框架，需实测） |

## 四、给「下一个实例」的检查单（由此对照提炼）

1. **落盘是什么？**（本地盘 / 9p / 网络卷）→ 决定读回腿与持久化方案，**必须实测**
2. **配置落在哪儿？**（`.env` / 启动脚本 / 环境变量）→ 决定改哪里
3. **CLI 开销多大？**（`send` / `-z` 各测冷热两次）→ 决定超时下限
4. **谁管进程？**（s6 / watchdog / 手工）→ 决定怎么重启、env 何时生效
5. **`identity.adapter` 有没有被占用？** → 有则**绝不能动**（LLM 路由字段）
6. **PATH 里有 `hermes` 吗？** → 没有就用绝对路径
7. **是否有软链/易失目录存依赖？** → 有则需持久化 + 自愈
8. **有没有遗留 WORKING 任务？** → 清账（并建议上游加「启动回收」）

## 五、一句话

> **同框架只保证「注入口的形状一样」（都是「另起一个带记忆的隔离回合」）；
> 落地差异决定「这条路好不好走」—— 落盘、配置落点、CLI 开销、进程管理，四项各不相同。
> ⇒ 适配器的价值，一半在实现通道，一半在**把这些差异变成可配的开关**。**
