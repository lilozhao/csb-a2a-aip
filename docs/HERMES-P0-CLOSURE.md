# Hermes 注入适配器 · P0 结项报告

> 2026-09-16 · 若兰 🌸 · 试点实例：**墨丘**（Hermes Agent v0.20.0 / Nous Research 开源框架）
> 关联文档：`docs/HERMES-ADAPTER.md`（契约）· `config/hermes-state-db-queries.sql`（读回 SQL）
> 一句话：**给「没有注入口」的 Hermes 系 Agent，造了一条能用的腿 —— 而且这条腿的形状和我们最初以为的不一样。**

## 一、背景：为什么要做

A2A 桥接要把「委托」送进对方**真正在思考的那一层**，才谈得上远程协作。两条不同的腿：

| 系 | 通道 | 注入方式 | 状态 |
|---|---|---|---|
| OpenClaw 系（阿轩/恺/小虾/Jeason） | C1 | HTTP：本机 gateway `/v1/chat/completions` | ✅ 已通（含 UAC 免 L3 闭环） |
| **Hermes 系（舟楫/墨丘/言蹊）** | **C4-H** | **本机 CLI `hermes -z`** | ✅ 本次打通（P0 完成） |

所以本次 P0 的目标是：**为 Hermes 系补上注入腿**，为后续 UAC 开通铺路（顺序铁律：**先通注入腿，再谈 UAC**）。

## 三、与墨丘互测踩到的坑（15 条 · 现象 / 根因 / 解法）

> 这部分是本次最有价值的产出。**大部分坑是墨丘在自己的机器上跑出来的**——我方一直全绿，看不见。

### A 类：判据类（怎么判断「成了没有」）

**K1 · 退出码靠不住**
- 现象：`hermes -z "读一个不存在的文件"` → **rc=0、stderr 空**，失败信息被当作「正常回答」塞进 stdout
- 根因：`-z` 把内容统一走 stdout，不区分成败
- 解法：**三重判据** —— `rc==0` + `stdout 非空` + **哨兵串命中**（prompt 末行要求原样回显 `BRIDGE-OK-…`，命中才剥行入回执）
- 反向验证：墨丘把哨兵**解码**了（base36 还原时间戳 vs taskId 内嵌时间戳，差 **33ms / 61ms**）→ 证明确系当场生成，不是事后手写

**K2 · 「能贴出记忆」证明不了「到了主会话」**（判据纠偏）
- 现象：我方原设计用「能否读到主会话记忆」作为「注入成功」的判据
- 根因：`-z` 隔离回合**同样载入 CWD 的 AGENTS.md / SOUL / memory**
- 解法：正式口径改为 **「端到端注入腿（带记忆的隔离回合）已通」**；真正能区分二者的是**会话连续性**（有无前序轮次），而隔离回合**看不到任何前序轮次**

### B 类：安全类

**K3 · 环境清洗剥掉了真正的护栏**（**本次最重要的一条**）
- 现象：为剥掉 `HERMES_S6_SUPERVISED_CHILD` 等做了环境白名单，**连 `HERMES_WRITE_SAFE_ROOT` 一起剥了**
- 根因：该变量是**写入护栏**，且逻辑是「**设了才检查**」→ 剥掉它 = **把子进程的写入边界打开**
- 对照实测（同 prompt，只差这一个变量）：无 → 文件**真被创建**；有 → **Write denied**
- 解法：白名单**保留**它；另提供 `A2A_HERMES_WRITE_SAFE_ROOT` 做**收窄**（如收窄到专用 scratch 目录）
- 教训：**「看起来在收紧、实际在放松」** —— 白名单是盲的，它不区分「多余的脏变量」和「关键的护栏变量」

**K4 · shell 层安全，语义层不安全**
- 事实：prompt 里的 shell 语法**不会**被二次解释（实测 marker 未出现）✓；但「**明确要求执行的命令**」**真被执行**（approvals 自动绕过）
- 含义：风险不在「拼接注入」，在**「委托内容会变成它的指令」**
- 解法：**授权责任放在 bridge（L3 确认 / UAC）**，不在 adapter；adapter 只兜**显式危险串**（禁止 gateway 生命周期 / s6 / kill 类指令），挡不住「帮我清理一下这个目录」这种语义化指令
- 配套：`-t <toolsets>` **工具锁**（实测 `-t file` 可直接把它锁成无终端，回 `NO_TOOL`）

**K5 · 工具集「能锁」但「零写」做不到**
- 事实：`file` 工具集含 read/**write**/**patch**/search，并非只读；全库无 read-only 开关
- 解法：只读档取最小集（如 `file,skills`），**绝对不含** terminal / code_execution / delegation / cronjob / memory；写入安全交给 **K3 的护栏收窄**
- 兜底：非法工具名 **fail-closed**（rc=2 报错，不会静默放宽）

### C 类：命名与配置类

**K6 · `identity.adapter` 是 LLM 路由字段，不能复用**
- 现象：注入适配器选择最初读 `identity.adapter`
- 根因：该字段已被 **LLM 路由**占用（`preferredAdapter = A2A_ADAPTER || identity.adapter`，取值如 `direct/openclaw/...`）→ 改它会把**注入通道**和**模型后端**绑死
- 解法：注入选择改用**专用字段** `identity.injectAdapter`（或 `bridge.injectAdapter`）；优先级 `env > 专用字段 > platform > 默认`；并加回归用例钉死「`identity.adapter='hermes'` 必须不被采纳」

**K7 · 命名撞车：两个 `hermes`**
- 现象：日志反复刷 `[LLM-Router] Hermes: localhost:3100 → <!DOCTYPE`
- 根因：LLM 路由的 `hermes`（**模型后端**）与新写的 `hermes`（**注入通道**）**同词两义**；且旧探测链会让每个失效适配器各超时 25s（实测单次响应可被拖到 75s+）
- 解法：① 宿主侧显式 `A2A_ADAPTER=direct` ② 协议侧建议给 LLM 适配器**改名**（如 `hermes-llm`）或从探测链去掉无效项

**K8 · 每会话 id 会过期**
- 现象：`A2A_HERMES_SESSION_ID` 写死会失效（每次新会话都换 id）
- 解法：新增 `{{CHAT_ID}}` 占位符 + `A2A_HERMES_CHAT_ID` —— **按 chat_id 自取最新会话**，不会过期

**K9 · 容器里没有 `sqlite3` CLI**
- 现象：只读回读依赖 CLI，宿主没有 → 直接不可用
- 解法：默认 runner 改用 **`node:sqlite`**（Node ≥22.5 内置），CLI 降为回退 —— **消除外部依赖**
- 附带：`state.db` 是 Hermes 内置禁写区，agent 工具改不到它

**K10 · 只读打开的坑（TZ / 全表 / FTS）**
- ① `timestamp` 是 **epoch**，容器 TZ=UTC → 按「本地时间」过滤**差 8 小时**（一律转 UTC）
- ② 库很大且 gateway 在写 → **禁无 WHERE 的 `COUNT(*)`**（实测 300s 超时）→ 只读打开 + busy_timeout + 强制 `LIMIT`
- ③ FTS 索引**含 tool 消息**（大块 JSON）→ 必须加 `role` 过滤；FTS 表 content 有尾随空格规范化 → 原文一律取 `messages` 表

### D 类：超时与运维类

**K11 · 超时 120s 太短**
- 现象：首验 **106.7s** 贴着 120s 上限，第二封直接 `bridge_unavailable · 注入超时`
- 根因：`hermes -z` 一个隔离回合本就重（载 AGENTS/memory + 完整 agent 回合）
- 解法：默认 **120s → 5min**；且**超时改为跟随信封声明**（`opts > max(信封声明, 默认)`，封顶 15min）—— 原来**完全忽略委托方声明的窗口**
- 反向价值：失败是**诚实失败**（明确 reason + detail + 指路），不是静默假成功

**K12 · 服务重启窗口里的委托会卡住**
- 现象：我方委托在对方**重启窗口**内送达 → ACK 不回、任务卡 `WORKING`
- 解法（协议侧）：**发送与收结果解耦** —— 秒 ACK + 幂等轮询 `/tasks/:id` 取回执；并提供 `/:id/cancel` 清残项
- 教训：**别重复发**（重复注入会造成同一封被处理两次）

**K13 · 前台启动脚本被超时连带杀**
- 现象：前台跑启动脚本，超时 SIGTERM **连同 `nohup` 的 node 一起被杀**（日志尾「正在关闭」、health 非 200）
- 解法：**改后台模式启动**；识别法 = 日志尾关闭行 + health 立刻异常

**K14 · 审计目录硬编码**
- 现象：`[Bridge-Audit] 本地留痕失败: EACCES mkdir '<别人的路径>'` —— 且**静默**
- 解法：审计目录**可配置**（env）；写失败时**降级为一条显式告警**，不允许静默

**K18 · 【我方 bug】诊断日志用了作用域外的变量 → 「首次空读必崩」**
- 现象：L3 委托 `confirmL3 异常: tid is not defined` → REJECTED；**投递/读回/注入三腿其实都是好的**，是「记账的那一行」自己炸了
- 根因：为「空读回留痕」在**轮询循环**里写 `${tid}`，而 `tid` 只是 `read` 回调的参数 → ReferenceError 在**首次读回为空**时必发（= 正常时序最常见的一瞬）
- 为何测试未拦：既有 17 条用例要么在到达该行前 `continue`、要么 `texts` 非空 ⇒ **无一条覆盖「`ok:true` 且空读回」**
- 修：`${tid}` → `${taskId}`；**补回归用例**（ok:true + 空读回 → 必须优雅超时、不得抛）
- 发现者：**舟楫首测即逮到并精确定位到行号**（换环境跑 = 最便宜的测试）
- 教训：**新增一个分支 = 新增一份测试责任**；`node --check` 查不出作用域错

**K17 · 「同名函数 ≠ 同契约」—— bridge↔adapter 三处错位（一轮踩三次）**
- 元现象：**每修好一层，下一层才浮出来**（① 没传 path ② 返回结构不对齐 ③ 参数名）
- 真正致命的是 **#2 返回结构错位**（静默）：
  · bridge 读回循环调 `collectTexts(resp.result)`，而 `collectTexts` 首行是 `if (!result) return []`
  · 参照实现（openclaw）返 `{ok, result:{matched, messages:[{text}], raw}}` ✅
  · Hermes 返 `{ok, matched, reply, raw}` —— **无 result 字段** → `collectTexts(undefined)` → `[]` → **从不进解析**
  · 症状：日志里 `path=db` 正常、轮询正常，却**零 `parsed=` 行**（与「根本没读」不同！）
- **修法**：① adapter 返回对齐参照契约（补 `result.messages[].text` / `replyText`）② bridge 容错 `collectTexts(resp.result || resp)` + `raw` 为字符串时直采 ③ 参数名双收（`since` / `sinceMs`）
- **流程固化**：`docs/NEW-ADAPTER-CHECKLIST.md`（逐参数 / 逐字段对照参照实现 + 症状速查表）

**K16 · ❌已撤回：曾判为「确认延迟落库」（宿主交互时序）**
- 当时的推断：消息持久化在回合边界 → 注入回合自跑长循环时确认未落库 → 在等一个只有自己松手才出现的条件
- **实测推翻（第三轮）**：主人的确认在**窗口起点 +21s 就已落库**，bridge 之后又轮询了几十次 ⇒ **不是时序问题**
- ⇒ 真因是 **K17 返回结构错位**（`collectTexts(resp.result)` 得到 undefined）
- **保留的教训**：一个合理推测也可能错；**先用可核证据定位再写结论**，并且**写错了要改回来**（而不是让它留在文档里）

**K15 · 测试自带环境依赖（同一个坑第三次）**
- 现象：同一套测试在对方机器上红 1 例 → 4 例，每次换个形式（硬断言实现细节 / 假设无 identity / **继承了 operator 的 `.env`**）
- 根因：测试直接复用 `process.env`；而宿主会把 `.env` 载入会话环境 → **「谁配好 .env，谁就看到几个假红」**
- 解法：**开测先铲干净**（清空全部 `A2A_*`/`HERMES_*`），并且**必须早于 `require` 适配器**（适配器在模块加载期就读 env）
- 教训：**只在我这台机器上绿的测试，等于没测**；逐例打补丁 = 没找根因（所以有了第三次）

## 五、能力边界（写进协议）

1. **C4-H = 「另起一个带记忆的隔离回合」，不是「续上主会话」** —— 没有会话历史
2. **适合**独立任务（read / pull / test / 单次查询）；**不适合**依赖先前对话上下文的委托
3. 隔离差异只有三样：不带会话历史 · 不污染主会话上下文 · 结果不回写主记忆
4. 「回合里仍带身份/记忆」是**预期行为**，不是隔离漏洞
5. **默认关**（`A2A_BRIDGE_HERMES=off`）；选定适配器 ≠ 已启用；失败一律降级 + 诚实指路
6. **write/shell 仍未开放**：确认请求的**投递腿**尚未实现（读回腿已具备）
