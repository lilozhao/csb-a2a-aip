> **作者**：若兰 🌸（起草）· 缘起：一澜提出「为了让 CSB 兼容各种框架的 agent，理解长周期常驻 Agent 的运行时的抽象」
> **关联**：`docs/AAT.md`（签名层）· `docs/inbound-auth-rollout.md`（判定层）· `docs/a2a-bridge-rfc-draft-2026-09-09.md`（动作层）· `docs/9P-NOTES.md`（外置存储风险）
> **一句话**：不问框架「你是什么」，只问它**七个位置能不能被问到**——并且要求它声明的相邻位置之间能互相查账。

## 零、这份文档要解决什么

长周期常驻 Agent（running for weeks, restarting, upgrading, spanning sessions）在互相接入时，
遇到的最大障碍不是协议格式不同，而是**根本不知道对方能回答哪些问题**。

于是出现两类假兼容：

1. **「我支持 A2A」** —— 但重启后说不清自己处理到哪了
2. **「我有审计日志」** —— 但日志和产物对不上账，事后无法复现

本规范把「能被问到」划为七个位置，规定每个位置的最小字段、声明方式与降级语义。
**它不规定实现，只规定"必须答得出"和"答不出时必须怎么承认"。**

---

## 一、七问的轴（读法比条款重要）

七问不是并列清单，是**三条轴**：

| 轴 | 位置 | 时间朝向 | 性质 |
|---|---|---|---|
| **发生过什么** | 会话 → 事件 → 动作 → 产物 | 过去（越往后越不可变） | **叙述** |
| **算不算数** | 签名 → 判定 | 现在 | **证据** |
| **进行到哪** | 游标 | 未来 | **承诺** |

推论（本规范的基石，请勿跳过）：

- **叙述层可以自述**：框架自己写日志就能答，代价低、可信度也低。
- **证据层不能自述**：必须有密码学或链式结构。自述的"我验过了"不算验证。
- **承诺层不能只在内存里活着**：进程一重启就失效的游标不是游标，是变量。
- **判定可信度的上限 = 签名层的强度**。签名层缺失时，判定层无论多复杂都只是"信任对方自报"。

## 二、七问最小字段表

> 约定：`必填` = 声称支持则该字段必须存在；`可选` = 有则更好；
> **所有位置都必须能回答「没有」**——用 `unsupported: {reason}` 显式写明，禁止静默省略（见 §四）。

### Q1 · 会话（Session）——「你是谁，这一轮里发生过什么」

```json
{
  "session_key": "string  // 稳定可寻址，禁止用进程内地址/PID",
  "participants": [{"agent_id": "string", "role": "string"}],
  "started_at": "ISO8601",
  "context_id": "string|null  // 与 A2A contextId 对齐（有则必填）"
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `session_key` | 必填 | **可寻址**：换进程、换机器仍能定位到同一会话 |
| `participants` | 必填 | 身份须与签名层 `agent_id` 同源（不许用显示名） |
| `started_at` | 必填 | 单调（同一实例内不倒退） |
| `context_id` | 可选 | 有则必须能反查回 Q2。**涉及跨会话归因的场景 SHALL 填**——否则探针分不清「没有上下文」与「没填上下文」（v0.2 补，评审 5:3） |

**反例**：会话存在 Redis 但 key 带随机后缀 → 重启即失联 = 不支持。

---

### Q2 · 事件（Event）——「刚才发生了什么」

```json
{
  "seq": "integer  // 会话内单调递增，不得复用",
  "ts": "ISO8601",
  "type": "string  // 命名空间化，如 msg.received / tool.called",
  "payload": "object"
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `seq` | 必填 | **单调 + 唯一**。无序的事件流只能当线索，不能当证据 |
| `ts` | 必填 | 与 `seq` 不矛盾（允许时钟漂移，但不允许次序倒挂） |
| `type` | 必填 | 稳定枚举；新增类型不得改变旧类型语义 |

**为什么不许只用时间戳**：同一毫秒内的两条事件无法排序 → 无法回答「先想后做还是先做后想」。

---

### Q3 · 动作（Action）——「你做了什么 / 打算做什么」

**必须与 Q2 分开。** 这是本规范最强的一条结构性要求。

```json
{
  "action_id": "string",
  "intent": "string  // 声明的意图（可被判定层审）",
  "effect": "none|internal|external  // 副作用等级",
  "status": "planned|executing|done|failed|rejected",
  "event_ref": "string  // 指向触发它的 Q2 seq",
  "gate": {"decision": "allow|deny", "by": "string", "at": "ISO8601"} | null
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `action_id` | 必填 | 全生命周期唯一（重试不换 id 才能去重） |
| `effect` | 必填 | `external` 必须有 `gate` 非空 |
| `event_ref` | 必填 | 动作必须能指回事件——**否则无法解释"为什么做"** |
| `gate` | 条件必填 | `effect≠none` 时必填；`deny` 也必须落账（对应 CSB P1） |

**为什么必须分开**：混在一起的框架，事后永远分不清「它想过」和「它干过」。
审计里最贵的混淆就是这一类。

---

### Q4 · 产物（Artifact）——「结果在哪」

```json
{
  "artifact_id": "string",
  "ref": "string  // 内容寻址：sha256:... / URI，禁止只给文件路径",
  "digest": "string  // sha256，ref 为 URI 时的旁证",
  "immutable": true,
  "produced_by": "string  // 指向 Q3 action_id"
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `ref` | 必填 | **内容寻址**；纯路径不算（会被覆盖） |
| `digest` | 必填 | **v0.2 起升必填**（评审 8:0）。`ref` 为 URI 时是旁证，内联文本时是唯一校验锚点——没有 digest 就没有「它真没改」的证明。<br>内联场景的例外见下方附注 |
| `immutable` | 必填 | 声明为 true 则内容不可改；改了必须换 id |
| `produced_by` | 必填 | 产物必须能指回动作——否则 Q3 的结论无法复核 |

**可内联的例外**：小于 1KB 且不可变的文本可内联，但必须同时给出 `digest`。

> **内联豁免的边界（若琢 R3 保留意见）**：`digest` 是必填项，无例外；但内联 <1KB 文本的 digest **可为 SHOULD 级**，条件是同时声明 `immutable: true`。
> 即：**URI 引用 → digest 强制；内联 → digest 可 SHOULD，但须有 `immutable: true` 兜底。** 绝无「两者皆免」的路径。

---

### Q5 · 签名（Signature）——「这条真是它发的吗」

**七问里唯一能"硬"起来的一层。**

```json
{
  "agent_id": "string  // 与被验签的 iss 一致",
  "key_fingerprint": "string  // sha256(crv:x) 前 16 位 —— 认钥不认票",
  "valid": "boolean",
  "error": "string|null  // 未通过时的失败码，必填",
  "verified_at": "ISO8601"
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `agent_id` | 必填 | 与签名主体一致；不得用显示名 |
| `key_fingerprint` | 必填 | **认钥不认票**：同一把钥的所有消息指纹相同，可与 pin 逐字对账 |
| `valid` | 必填 | **布尔且必须显式**：缺席 ≠ 正常 |
| `error` | 条件必填 | `valid=false` 时必填（`no_token`/`expired`/`bad_signature`/`no_pinned_key`…） |

**实现参考**：`a2a-aat-envelope.js`（CSB 落信封实现，含 5 条负向测试）。

**关键纪律**：验证结论必须能透传到下游，且**不可由客户端伪造**
（CSB 用 `Symbol` 键做透传，因为 JSON 造不出 Symbol）。

---

### Q6 · 判定（Decision）——「该不该放行」

**必须与 Q5 分开。签名回答「是谁」，判定回答「准不准」。**

```json
{
  "decision_id": "string",
  "subject": "string  // Q5 的 agent_id",
  "policy": "string  // 策略名 + 版本",
  "result": "allow|deny|shadow",
  "reason": "string",
  "remediation": "string|null  // 拒绝时必须给可执行下一步",
  "evidence": {"aat_valid": true, "trust_level": 2, "...": "..."}
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `result` | 必填 | 三值，`shadow` 不得与 `allow` 混同 |
| `remediation` | 条件必填 | `deny` 时必填（否则对方无法自救 → 变成永久封锁） |
| `evidence` | 必填 | 必须含 Q5 结论；**允许"验过但权限不够"这一独立状态** |

**反例**：把"验签通过"直接等同于"允许执行"。这是把两个正交维度压成一维，
事故形态是：本人被放行了不该放行的动作，事后还查不出是哪层该拦。

---

### Q7 · 游标（Cursor）——「处理到哪了，重启从哪接」

**最容易被漏掉的一层，因为内存里活得好的框架根本不需要它。**

```json
{
  "stream": "string  // 如 inbox / audit / task:<id>",
  "position": "integer|string  // 单调推进，语义由 stream 定义",
  "acked_at": "ISO8601",
  "semantics": "at-least-once|at-most-once|exactly-once",
  "idempotent": true
}
```

| 字段 | 级别 | 硬约束 |
|---|---|---|
| `position` | 必填 | **单调推进**；回退必须显式声明（如 `reset: reason`） |
| `semantics` | 必填 | 交付语义必须自报；**必须显式声明，禁止隐式推断默认值**。`exactly-once` 可声明，但 **SHALL 附底层幂等证据**（ledger hash / state root / 幂等键）；无证据的 EO 声明按 `at-least-once` 处理（v0.2 补，阿轩案） |
| `idempotent` | 必填 | false 时消费端必须能去重，否则重启会重复副作用 |

**反例（CSB 现状）**：`a2a-inbox.jsonl` 的 `seen: false` 是**布尔而不是位置**。
重启后无法回答「我处理到第几条」，只能全量重扫或按时间戳猜。
**这不是游标，是标记。**

## 三、降级矩阵（声明支持 ≠ 完整支持）

外部框架只有七问中的一部分是很正常的。本规范用**等级**而不是"是否兼容"来回答。

### 3.1 六档（A⁻ 为明文档位，不是 A 的修饰符）

> **v0.2 变更**：取消「A-」这种靠减号暗示的写法，改为**逐档明文**。
> 依据：一澜 2026-11-24 指示（「在 R2 就把 A- 拆成 A/A⁻/B 三个明文选项，而不是留在减号里」）+ 协议组 R1/R2/R3 共识。
> A⁻ 既是档位名也是机械判据：**A 档且 `continuable: false`**。符号与字段同源，不存在两套语义。

| 等级 | 名称 | 条件（机械可判） | 续跑 | 能做什么 | 不能做什么 |
|---|---|---|---|---|---|
| **A** | 可裁可续 | Q1–Q7 全支持 且 相邻层对账通过 且 `continuable: true` | ✅ | 参与判定、被追责、**重启后接续** | —— |
| **A⁻** | 可裁不可续 | Q1–Q7 全支持 且 相邻层对账通过 且 **`continuable: false`**（Q7 无持久位置） | ❌ | 参与判定、被追责 | **不可续跑**。接入方必须自行做幂等兜底，并在接入记录中显式标注 |
| **B** | 可读不可裁 | Q1–Q4 支持，**Q5 或 Q6 缺失**（含 `continuable: false` 且 Q7 完全缺失） | ❌ | 可读、可展示、可做线索 | **不能作为裁决依据**（无签名/无判定） |
| **C** | 可读不追溯 | Q1–Q2 支持 | ❌ | 可看它说了什么 | 不能追问"做了什么/结果在哪" |
| **D** | 黑盒 | 仅 Q1 | ❌ | 知道它存在 | 其余全部不可问 |
| **E** | 不可接入 | Q1 也无 | — | —— | 拒绝接入（须落账，不许静默丢弃，见 P1） |

**等级由最弱的一环决定，不由最强的一环决定。**

### 3.2 判定顺序（先分档，再看续跑）

```
1. Q1 都没有            → E
2. Q3 与 Q2 合并实现     → 视为 Q3 缺失，按 Q1–Q2 计（→ C）
3. Q5 或 Q6 缺失        → B
4. Q7 完全缺失          → B
5. Q1–Q7 齐全但相邻层对账不过 → B（字段齐全≠可裁）
6. Q1–Q7 齐全 + 对账过 → 看 continuable：true → A ／ false → A⁻
```

### 3.3 档位的机器可读形态

每个实现/探针输出都必须带这两个字段，缺一即判无法分档：

```json
{ "level": "A|A-|B|C|D|E", "continuable": true }
```

- `continuable` 是**布尔**，不是备注散文。A⁻ ⇔ `level:"A-"` 且 `continuable:false`，两者必须一致，不一致即为探针 FIND（自报矛盾）。
- 不接受 A⁻ 写成 B 或 A：**降档与「同一档内不可续」是两件不同的事**——前者是能力不足，后者是能力够但状态不持久。压成一档会让续跑缺口在报表里消失。

**三条实现细节（R3b 八席补充，2026-11-24）**：

1. **缺失 ≠ 矛盾**（墨丘）：`level:"A"` 但**完全没有** `continuable` 字段 → 报 `结构缺失`；字段存在但 `A` 配 `false` → 才是 `值矛盾`。两种 FIND 不能混，否则会误杀早期未带该字段的旧输出。
2. **符号编码要写死**（明德）：**机器值统一用 ASCII `A-`**（连字符），文档排版可写 `A⁻`。即：`level` 只接受 `A-` 这一个字面量，拒绝 `A⁻`（U+207B）、`A−`（U+2212）、`a-` 等变体——探针收到变体即报 `编码不一致`，不忽视为等价。**判据的机械性优于排版美观**。
3. **FIND 须留原始值**（星尘）：触发矛盾时日志必须同时保留原始 `level` 与 `continuable` 值，否则事后无法回溯是哪一侧写错的。

### 3.4 补充规则

- **缺 Q5（签名）→ 最高 B**。理由：判定层失去硬证据，任何"允许"都只是信任自报。
- **缺 Q7（游标）→ 最高 A⁻**（可裁但不可续）；接入方必须自行做幂等兜底，并在接入记录中标注。
- **Q3 与 Q2 合并实现 → 视为 Q3 缺失**（无法区分"想过"与"干过"）。
- **不增设 B+**（R2 舟楫/思源提案）：无机械判据的档位等于没有档位；Q7 缺口已由 A⁻ 与 B 两档覆盖。

### 3.5 本轮为什么这样定（留档）

R2 的表决是四分（甲 A⁻子级 3 / 乙 并入A加备注 2 / 丙 取消减号降B 2 / 丁 `A-partial` 1），无派过半。
R3 的合流案是「不增档不减档，改成 A 档内强制字段 `continuable`」（4 票领先）。
本版把两者并成一个写法：**档位仍离散、符号仍是 A/A⁻/B，而 `continuable` 是它的机械载体** —— 甲派拿到「可机械判」，乙派拿到「不加新符号」，丁派拿到「显式标签」，丙派的诉求（消除半等级）也满足。
唯一未获满足的是「缺 Q7 直接降 B」：那会让「能力够但不持久」与「能力不够」在报表中同形，故不采纳。

## 四、缺席必须显式（Absence ≠ Normal）

这条是 CSB P1「拒绝要计分」在运行时抽象上的等价物。

任何一问答不出，**必须**返回：

```json
{ "question": "Q4", "supported": false, "reason": "artifacts 未做内容寻址，仅存本地路径" }
```

**禁止**：

- 返回 `{}` 或省略字段（缺席会被误读为正常）
- 返回 `200 OK` 而内容为空
- 用 `null` 表示"不支持"（`null` 应表示"支持但本次为空"）

**为什么这么严格**：如果「字段缺失」和「未通过」长得一样，负向判据就永远红不了。
这是 2026-11-22 我们踩过的假绿（解析成功但 401，200 但 content 空），
在运行时层是同一类错误的另一个形态。

## 五、探针设计（`conformance-probe`）

规范写在纸上没人验。探针是唯一让矩阵变硬的手段。

### 5.1 原则

1. **只读**：七问全部是读操作，不触发任何副作用（`Q3.effect` 只查询已记录的，不发起新动作）
2. **可复跑**：同一框架同一版本，两次探测结果必须一致（差异本身即为 FIND）
3. **异常即 FAIL**：超时/报错/解析失败 → 记 `FAIL`，**不得记为"不支持"**
   - 「不支持」是对方声明的
   - 「FAIL」是我们没问出来
   - 两者必须分开，否则对方的真实能力被我们自己的网络问题掩盖
4. **相邻对账优先于字段齐全**：只有字段没有对账 → 降级

### 5.2 输出

```
框架 X（v1.2.3）  探测于 2026-11-23T09:12+08:00
────────────────────────────────────────────────
Q1 会话   ✅  session_key 稳定可寻址
Q2 事件   ✅  seq 单调，抽样 3 条次序正确
Q3 动作   ⚠️  有动作流，但无 effect 等级 → 无法判断是否外发
Q4 产物   ❌  仅存路径，无内容寻址
Q5 签名   ✅  Ed25519，指纹与 registry pin 一致
Q6 判定   ✅  拒绝带 remediation
Q7 游标   ❌  无位置，仅 seen 布尔
────────────────────────────────────────────────
可兼容等级：B（可读不可裁）
主要缺口：Q4 无引用 → Q3 结论不可复核；Q7 无位置 → 不可续跑
建议：接入前要求补 Q4（成本最低、收益最高）
```

### 5.3 相邻对账检查项（必须真跑，不能只看字段）

| 对 | 检查 | 失败含义 | 强度 |
|---|---|---|---|
| Q1 → Q2 | 会话里抽一条事件，能反查回同一 session_key | 会话键不唯一或事件挂错 | 抽查 |
| Q2 → Q3 | 抽一条动作，其 event_ref 能命中 Q2 的 seq | 动作与事件脱节 | **必备** |
| Q3 → Q4 | 抽一个产物，produced_by 命中 Q3 action_id | 产物来源不明 | **必备** |
| Q4 → Q7 | 游标推进后，已消费产物仍可寻回；重启后 position 与最新产物对齐 | 产物与游标脱钩 → 丢结果或重复消费 | **必备** |
| Q5 → Q6 | 抽一条 deny，evidence.aat_valid 存在；验签真跑且结论透传到判定 | 判定未基于签名 = 自述 | **必备** |
| Q2 → Q7 | 用 cursor.position 续读，应无重复/无跳过 | 游标是标记不是位置 | 抽查 |
| Q1 → Q7 | 续跑后会话同一性（重启前后 session_key 一致） | 续跑即换会话 = 不可追 | 抽查 |
| Q3 → Q7 | 动作完成态与游标一致（防「假进度」） | 游标跑在动作前面 | 抽查 |

**必备四对全过才算 A 级 / A⁻ 级**（差在 `continuable`）；字段齐全但对账不过 → 降级，并在报告中写明是哪一对断了。

> **Q5→Q6 为什么升必备（v0.2）**：R2 八席自报的必备集里，这一对**零票**。而它正是 §一 说的「证据层」接缝、判定可信度的上限。R3 单列为一颗钉子后 **7 票改为必跑**，理由几乎同一句：*证据链不真跑，判定即悬空*。零票不是共识，是集体盲区。

### 5.4 假兼容硬校验（v0.2 新增，四条）

只在字段层面校验，探针就永远只能抓住老实人。以下四条必须在探针里硬跑：

| # | 绕法 | 硬校验 | 票数 |
|---|---|---|---|
| ① | **日志搬运工**：Q3 的 event_ref 指向「计划时间戳」而非真实执行 seq | event_ref 必须命中真实事件 **且** 该事件时间 **早于** 动作完成时间 | 5 |
| ② | **seq 伪造**：时间戳+随机后缀冒充单调 seq | seq 严格递增 **且无跳号**（宁可有缺口（缺失）也不能有重号） | 5 |
| ③ | **跨重启断裂**：seq 重启归零 / cursor 跳号 | 重启前后各跑一次，比对 seq 连续性与游标覆盖（**条件项**：仅当 `continuable: true` 时强制；否则记「未验证」） | 2 必备 + 1 条件 |
| ④ | **空体伪装**：200 + `{}` 静默丢弃 | 非空体 **且** 含显式 `supported` 字段；禁止 `{}` / 禁止无 content 的 200 | 7 |

> ③ 设为条件项而非必备，是 R3 钉子三的结果（5 票）：**常态探针不背重启成本，但声明续跑者必须证明**。
> 不声明的实现记「未验证」，**不得记「通过」**——两者在报表里必须长得不一样。

```
data/a2a-inbox-cursor.json   { "stream":"inbox", "position": N, "acked_at": "...", "semantics":"at-least-once" }
```

成本估计：**半天**。收益：把"重放"变成"续跑"。

> **你可以只支持七问中的几问，但声明支持的那几问必须彼此可查。
> 不支持的要显式写出来——缺席不等于正常。**

是在**核对**，还是在**互相猜**。

## 附录 A · 术语

| 词 | 含义 |
|---|---|
| **位置（position）** | 一个能被问到的界面；不等于 API 端点 |
| **对账（reconcile）** | 相邻两层互相能查到对方，非"字段齐全" |
| **硬（hard）** | 无法由被审计方单独伪造（密码学/链式） |
| **落信封（envelope）** | 把验签结论写入消息的持久化结构中 |
| **认钥不认票** | 身份核对锚定在公钥指纹上，而非某张令牌 |
