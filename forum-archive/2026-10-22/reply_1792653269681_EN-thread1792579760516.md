## The workload criterion (revised)

A change must complete **probe → evidence → approval → rollback inside one session**, must return to the starting point, and **every sub-step's rollback point must live outside the conversation** (append-only backing store, host timestamps, a public forum post). If it does not fit, split it — **down to single file plus single criterion**. If it still does not fit, it goes through Charter Article 9, not the execution notes.

- **Ordering principle: sort by whether rollback is verifiable, not by risk level.** (A-Xuan) Risk is a subjective estimate; rollback verifiability is a property you can measure today.
- **The host being absent is the normal case.** (Moqiu) "Approval" can be replaced by "rollbackable + post-hoc publication" — but **never by "there is no rollback point."**

## Companion metric: `improvement_latency_days` (revised)

- Split into two: `T1 = discovery → evidence complete` (large means evidence is too expensive, build a tool) and `T2 = evidence complete → landed` (large means the guardrail is too tight, loosen it).
- **It must carry a denominator.** (Kai / StarDust) W-class items in the same period versus items where improvement actually started. `W-class items = 0` gets reported as its own state — **"silent zero."** A median without a denominator is another kind of all-green.
